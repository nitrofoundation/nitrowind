# Expo 56 Dynamic Engine Fixes

This note records the Expo 56 / RN 0.85 debugging work for the native dynamic style engine.

## Scope

- Keep first paint in JS (`resolveStyles`) and subsequent dynamic updates in the C++ Fabric engine.
- Support bridgeless Expo 56, system light/dark changes, theme variables, container queries, and Tailwind v4 palette/spacing output.
- Verify the example app visually on the iOS simulator after rebuilding JS and native code.

## Fixes

| Area                                    | Root Cause                                                                                                                                                                           | Fix                                                                                                                                                                                                                                                                                                                                |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bridgeless UIManager capture            | `setBridge:` does not run in the Expo bridgeless host, so native commits had no UIManager.                                                                                           | Lazily capture `UIManagerBinding` from a live JSI runtime when a shadow node is converted, then register the Fabric layout observer.                                                                                                                                                                                               |
| Shadow node linking                     | The raw React ref was passed to Nitro instead of the Fabric shadow-node wrapper.                                                                                                     | Extract `__internalInstanceHandle.stateNode.node` before creating the native shadow node handle.                                                                                                                                                                                                                                   |
| System appearance                       | Native mode still had a JS `Appearance` listener, so automatic system light/dark changes could pass through JS even though iOS/Android already observe those changes natively.       | Remove the JS `Appearance` bridge in native mode. Swift/Kotlin own system appearance changes and push them directly into C++/Fabric; JS `Appearance` is fallback-only when the native engine is unavailable.                                                                                                                       |
| Forced light/dark system flips          | Native JS listeners reported `ColorScheme` for every system environment notification, even when the app was forced to light/dark and the effective color scheme did not change.      | Track the last native runtime snapshot on iOS/Android and emit only real dependency diffs. System appearance flips under forced light/dark now push native state but do not notify JS hook subscribers unless the effective runtime value actually changed.                                                                        |
| Stale screen remount theme              | With no JS listener installed, a screen remount after a native-only system theme change could read a stale cached JS snapshot for first paint.                                       | Make native-mode `runtime.current` refresh from `Platform.getCurrent()` on demand. This keeps newly navigated screens in sync without installing a JS runtime subscription.                                                                                                                                                        |
| Theme variables                         | `var(--color-*)` styles were treated as Theme-only, so system dark/light overlays could be missed.                                                                                   | Mark CSS variable values as Theme + ColorScheme dependent.                                                                                                                                                                                                                                                                         |
| Tailwind OKLCH palette                  | Tailwind v4 default palette variables are OKLCH; native Fabric commits cannot parse OKLCH strings.                                                                                   | Normalize function-form theme colors (`oklch`, `oklab`, `lab`, `lch`, `rgb`, `hsl`, `color`) to hex at compile time.                                                                                                                                                                                                               |
| JS/native color parity                  | JS first paint used `rgb(...)`; native Fabric commits cannot parse those color strings consistently.                                                                                 | Normalize JS colors to native-safe hex, then convert hex color props to RN processed numeric ARGB before C++ RawProps commits.                                                                                                                                                                                                     |
| Native recompute precedence             | JS first-paint class styles were stored as inline overrides in the native registry, so base styles like green could overwrite later container-query recomputes like amber.           | Store only true user inline styles as native inline overrides; native class recomputes can now override first-paint class styles.                                                                                                                                                                                                  |
| Tailwind spacing / padding              | Generic length parsing did not evaluate `calc(var(--spacing) * n)`, so `p-*`, `gap-*`, `h-*`, etc. could remain invalid CSS strings.                                                 | Reuse the existing arithmetic length evaluator for generic RN values and pass the rule variable resolver into `toRNValue`.                                                                                                                                                                                                         |
| Hex colors misread as lengths           | The length tokenizer extracted digits from `#111827`, compiling `text-on-surface` as a number.                                                                                       | Require the entire expression to be consumed by length/arithmetic tokens before treating it as a length.                                                                                                                                                                                                                           |
| Container initial measurement           | `link()` runs from a React ref callback after Fabric's `shadowTreeDidMount`; static screens could miss the first measurement.                                                        | Add `LayoutObserver::remeasure()` and call it after registering a container so the current committed tree is measured immediately.                                                                                                                                                                                                 |
| Container query child binding           | Query descendants can link after their nearest container was already measured, leaving their `containerTag` unset.                                                                   | Trigger the same native remeasure/association pass when any node that reads `ContainerSize` links.                                                                                                                                                                                                                                 |
| Imperative native width changes         | RN `setNativeProps` can visually change width without a React render, but the C++ container registry also needs that new container size.                                             | Add `setNativeProps` that resolves the native tag, commits through the C++ registry when possible, and pushes container width into the native container-size registry for query recompute.                                                                                                                                         |
| Imperative native height/color changes  | The native `setNativeProps` helper only pushed container size when `width` was numeric, and imperative color commits skipped native color processing.                                | Accept width or height overrides, preserving the missing axis with the last measured value, retry registration for either axis, and run imperative style commits through native color processing.                                                                                                                                  |
| Container dependency expansion          | Native `depsFromMask()` only expanded bits `0..7`, dropping `ContainerSize` bit 8.                                                                                                   | Expand through generated `StyleDependency::CONTAINERSIZE`.                                                                                                                                                                                                                                                                         |
| JS tree re-rendering on runtime changes | The provider subscribed globally and stored the full runtime snapshot in React state, so theme/appearance changes could wake context consumers even though C++ committed the styles. | Make `NitrowindProvider` expose stable controls only. Components start the native platform listener but do not subscribe to dependency changes in native mode. Runtime hooks (`useNitrowind`, `useRuntimeSnapshot`, `useColorScheme`, `useTheme`, `useDimensions`, `useInsets`, `useFontScale`) opt into JS re-renders explicitly. |
| Example theme toggle re-rendering       | The sample `ThemeToggle` used `useNitrowind()`, so pressing the toggle legitimately re-rendered that component while the native engine updated styles.                               | Make the example toggle imperative: read `runtime.current.colorScheme` only in `onPress` and call `runtime.setColorScheme(...)` directly, with no React state or runtime hook subscription.                                                                                                                                        |
| Native runtime priming                  | The C++ engine needed platform values without requiring a JS listener subscription.                                                                                                  | Make native `Platform.getCurrent()` push current runtime state to C++ and cache the first native snapshot on the JS side; only explicit runtime hooks/subscriptions install the JS native listener that keeps the JS snapshot fresh.                                                                                               |
| Hook-only JS updates                    | Native styled components called `runtime.start()`, which used to install JS runtime listeners needed only by `useNitrowind` / `useTheme` style hooks.                                | Split native startup from native subscription. Styled components prime native state only; `runtime.subscribe(...)` is the sole path that installs `Platform.addRuntimeChangeListener`, so only components using explicit runtime hooks re-render on matching dependencies.                                                         |
| Named adaptive themes                   | Named palettes could be merged under the active light/dark scheme overlay, making custom theme buttons look unchanged in system dark mode.                                           | Keep light/dark scheme overlays scoped to the built-in adaptive themes; named themes now preserve their own semantic tokens in JS first paint and C++ native recomputes.                                                                                                                                                           |
| Example container text visibility       | The first container demo used `hidden` display toggles and row switching, which could leave the detail text missing or squeezed while native width changes were repeated.            | Keep the text mounted at every width, then use container-query color and spacing changes to demonstrate native restyling without relying on clearing a stale `display: none` prop.                                                                                                                                                 |
| Border axis utilities                   | Tailwind emits logical axis declarations such as `border-inline-width` and `border-block-width`, which do not map directly to React Native style props.                              | Expand logical axis declarations into physical RN edge props (`borderLeftWidth` / `borderRightWidth`, `borderTopWidth` / `borderBottomWidth`, and matching edge colors).                                                                                                                                                           |
| Native box shadow                       | The compiler only emitted RN's `boxShadow` string, which is not enough for native shadow rendering paths that use React Native's platform shadow props.                              | Keep `boxShadow` and also derive `shadowColor`, `shadowOffset`, `shadowOpacity`, `shadowRadius`, and `elevation` from the first Tailwind shadow layer.                                                                                                                                                                             |
| React Native import capture             | Example code had to import host components from `nitrowind` directly instead of writing normal `react-native` imports.                                                               | Add a Metro import rewrite for project files that redirects styled host components (`View`, `Text`, `Pressable`, etc.) from `react-native` to nitrowind wrappers while leaving types and non-host RN APIs on `react-native`.                                                                                                       |
| Third-party prop color mapping          | `withNitrowind` only handled the main `className` / `style` path, so component props like `tintColorClassName` or `placeholderTextColorClassName` could not map token colors.        | Extend `withNitrowind` with Uniwind-style auto/manual mappings for `*ClassName`, `*ColorClassName`, and explicit `{ fromClassName, styleProperty }` mappings.                                                                                                                                                                      |
| Native prop color accents               | First paint could map props like `colorClassName` or `placeholderTextColorClassName`, but the C++ engine did not own those prop colors for later theme changes.                      | Register native accent descriptors for ActivityIndicator, Image/ImageBackground, TextInput, and Switch color props. C++ stores accent class names and recomputes/commits those props with the owning host node on theme/color changes.                                                                                             |
| Placeholder color shorthand             | `placeholder:text-*` compiled as ordinary `color`, so TextInput placeholders did not receive `placeholderTextColor`.                                                                 | Map placeholder selectors to `placeholderTextColor` in the compiler and include that prop in JS/native color normalization.                                                                                                                                                                                                        |
| Example orientation                     | The Expo example was locked to portrait in both app config and the checked-in iOS prebuild.                                                                                          | Set Expo orientation to `default`, update iPhone/iPad `UISupportedInterfaceOrientations`, and read iOS dimensions from the key window bounds so orientation changes update native runtime dimensions.                                                                                                                              |
| React Native className types            | The example carried its own `nitrowind-react-native.d.ts` augmentation.                                                                                                              | Move the React Native prop augmentation into `nitrowind` (`src/types/react-native.ts`) and load it from the package type entry; the example now consumes package-owned types instead of maintaining its own declaration file.                                                                                                      |
| Reanimated tap resize demo              | The layout transition example only changed width, making it harder to verify tap-resize behavior.                                                                                    | Update the Animations screen to use a clearer `layout-linear-transition` tap-resize sample that changes both width and height.                                                                                                                                                                                                     |

## Verification

- `cd packages/nitrowind && yarn test && yarn typecheck && yarn build` passes: 100 tests.
- `cd example && yarn tsc --noEmit` passes.
- `cd example && yarn expo run:ios` succeeds with 0 errors and only the known duplicate `-lc++` linker warning.
- Metro must be restarted with `--clear` after compiler changes because the example consumes built `nitrowind/compiler` output and Metro workers cache the transformer.
- Final container screenshots verified in light and dark mode:
  - padding/spacing is visible (`p-4`, `px-*`, `py-*`, `gap-*` are numeric RN values),
  - `text-on-surface`/`text-muted` render with correct light/dark contrast,
  - the first container demo keeps label/detail text mounted and readable while `@min-[280px]` changes spacing/color natively,
  - `bg-emerald-500 @min-[300px]:bg-amber-500` is green at 280px and flips to amber after a native `setNativeProps` width update to 360px, without React state.
- Default styled components no longer subscribe to JS runtime dependency changes when the native engine is present. System appearance, theme, dimensions, insets, RTL, rem and font scale flow into Swift/Kotlin -> C++ -> Fabric commits; JS only re-renders components that mount explicit runtime hooks such as `useNitrowind`, `useTheme`, `useColorScheme`, `useDimensions`, `useInsets`, or `useFontScale`.
- Native-mode `runtime.start()` no longer calls `Appearance.addChangeListener` or `Platform.addRuntimeChangeListener`; regression tests cover that listener installation happens only after `runtime.subscribe(...)`.
- Forced light/dark ignores OS appearance flips at the JS listener level because native platforms now emit dependency diffs instead of broad dependency lists. Auto/system still updates the native engine when the effective color scheme changes.
- Screens mounted after a native-only system theme change read a fresh native snapshot via `runtime.current`, so navigating back no longer waits for a later runtime change to correct first paint.
- The Expo theming screen now includes native `runtime.setColorScheme(...)` controls and named adaptive theme buttons (`Base`, `Ocean`, `Ember`, `Graphite`) that restyle semantic token swatches through native commits.
- The first container-query example keeps its label and detail text visible at the measured native width after repeated imperative `setNativeProps` width changes.
- Border screenshots show `border-x-4` and `border-y-4` rendering through native edge props.
- Transform screenshots show `shadow-*` demos rendered from native RN shadow props in the first viewport.
- The example app now imports host components from `react-native`; Metro rewrites those app imports to nitrowind wrappers at bundle time, preserving normal RN type/helper imports.
- React Native `className` / color prop typings are provided by the `nitrowind` package; the example-local augmentation file was removed.
- The example iOS app supports portrait and landscape orientations in the checked-in prebuild. `simctl io ... rotate` is not available in this Xcode, so orientation support was verified through `Info.plist` and the rebuilt iOS target.
